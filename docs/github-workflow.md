# GitHub Workflow

GitHub turns SEO recommendations into trackable work.

## Recommended structure

- Keep this repo public if it only contains templates and examples.
- Keep site-specific strategy in a private fork or private repo when needed.
- Use issues for work items.
- Use pull requests for site changes.
- Use labels to group work.

## Issue labels

Suggested labels:

- `seo`
- `content`
- `technical-seo`
- `internal-linking`
- `metadata`
- `schema`
- `high-impact`
- `quick-win`
- `needs-data`
- `blocked`

## Issue quality bar

Each SEO issue should include:

- Problem
- Evidence
- Recommended fix
- Acceptance criteria
- Verification steps
- Priority

## Pull request checklist

For SEO-impacting PRs, check:

- Title and meta description
- Canonical
- Robots/indexability
- Heading structure
- Internal links
- Schema
- Sitemap impact
- Redirects
- GSC follow-up date

## Suggested automation

Use GitHub issues for:

- Content briefs
- Metadata updates
- Technical SEO fixes
- Internal linking passes
- Schema work
- Monthly reporting tasks

Use private GitHub projects for site-specific strategy if the data is sensitive.
